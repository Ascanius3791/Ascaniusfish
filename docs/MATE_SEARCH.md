# Mate search (#78)

The mate verifier behind `UCI_Engine::verify_mate()`. Keep it in sync with `src/mate_search.cpp`.

`lib/mate_search.hpp` / `src/mate_search.cpp`: `minimax_checkmate_only()` is a search of its own (not `minimax()`) that only asks "does the attacker mate within r plies?", the null window at the mate score `INT_MAX - r`. No eval, null move, LMR, LMP, quiescence or extensions, and the defender's moves are never pruned, so every mate it finds is real. `FULL_WIDTH` is complete: `find_mate()` deepens r upward, so its first hit is the quickest mate. `CHECKS_ONLY` (the attacker only checks, or evades when in check) is fast and sound, not complete. Ordering: the TT move, then the attacker's checks before its quiet moves, each by the fewest flight squares left to the defending king, and the defender's moves by the most it keeps; both counted without making the move (`Node_Info`), and `gives_check()` tells a check unmade, so the last attacker ply makes only checks. A child within `SyzygyProbeLimit` pieces that is not a table win for the attacker is cut (a cursed win counts: the 50-move rule and repetitions are ignored here); with Gaviota a ≤5-piece child gives its exact distance. Its own TT: 2^`MATE_TT_BITS` (19) entries of 16 bytes = 8 MB, allocated on the first search, holding per position and attacker a mate within n (any mode), none within n by full width (both modes), none by checks (`CHECKS_ONLY` only).

It is a **verifier only**: `UCI_Engine::verify_mate()` (`src/uci.cpp`) checks every mate (not a TB score) that line 1 of an iteration claims, before it is reported or ends the deepening: checks-only up to the claim, then full width below what that found (the quickest, if it finishes), or else full width up to the claim, on max(`MATE_VERIFY_MIN_NODES`, the nodes spent so far). Confirmed: the score is the mate search's, and so are the line and move when the root side mates; `info string mate claim P plies confirmed: Q plies, the quickest|checks`. Refuted (none within the claim, proven) or unchecked (out of budget or time): the line is printed as the search gave it and the deepening goes on. `make mate-suite` (`tools/mate_suite`; `tools/mate_suite.epd`, 430 Lichess mate puzzles, every N confirmed by Stockfish 15) gives the hit rate per N at 1 s, a hit being `mate N` with N the shortest; `tools/mate_suite claims` counts the verdicts on any position list (`bench` built in). `diagnostics/mate_search_test.cpp` runs the mate search alone on the suite, `diagnostics/quiescence_mate_test.cpp` checks every mate `minimax_tactical()` returns from positions in check. `mate_confirmed()` is the check for `minimax_tactical()` out of budget with a skipped check-back evasion (deepened from the claim, since the skipped evasion may last longer); `diagnostics/quiescence_skip_mate_test.cpp` is a position built to reach it (a real search only gets there after 30 checks or forced moves in one quiescence line). Numbers: `docs/measurements/mate_suite_2026-10-03.md`.
