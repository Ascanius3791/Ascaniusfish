# NNE dataset: 533k labelled quiet positions from Lichess (#50)

Commit a8bc3b5 (`tools/nne_data`, built by `make tools/nne_data`, TT_EXPONENT=13).
Design: `docs/NNE_DESIGN.md`, "Data".

```
./tools/nne_data run ~/lichess/lichess_db_standard_rated_2014-06.pgn.zst \
                     ~/lichess/lichess_db_standard_rated_2014-07.pgn.zst out=data/nne jobs=6
```

- Dumps: Lichess standard rated, June 2014 (182 MB, 961,868 games) and July 2014
  (200 MB, 1,048,440 games), from database.lichess.org. June alone keeps 265k
  games, not enough, so July was added. Neither dump is in the repo.
- Wall time 1 h 30 min on 6 workers (596% CPU, 32,000 s user). The depth-6 labels
  take 24,700 s of that, 46 ms per position on average. Peak RSS 249 MB.
- Output: `data/nne/{train,valid,test}.tsv` (git-ignored, 203 MB with the part files).

No game failed to load. Lichess 2014 SAN over-disambiguates (`Rfe1` with the
a1 rook blocked), which `gui/move_tree.hpp` now reads (3eea0e7). 405 duplicate
positions were removed, which leaves **532,902 positions**: train 426,371,
valid 53,355, test 53,176.

Per game: a random ply in [16, plies], then the first position from there that
is not in check and whose quiescence score equals the static eval. The label is
`ucinewgame; position fen …; go depth 6`, with the tables in `~/syzygy-nr` loaded.
12 labels checked against `ascaniusfish_uci` (built with TT_EXPONENT=13) were all
identical.

So the typical correction is about the size of ε = 50 cp in the loss (median
\|c\| 68). A 5% tail beyond 600 cp is left even in quiet positions, which is
what the log loss is meant to keep from dominating.
