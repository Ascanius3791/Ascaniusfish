# Seeded vs cold search to the stored depth + 1 (#79)

Engine: bdb6aa0 (the `hint` command; same search code as the run, which was on its
working tree). Command: `flock -w 3600 /tmp/ascaniusfish-heavy.lock ./tools/ptt_seed n=30 store_ms=5000`
(UseNNE on, no tablebases, one engine process, empty TT before every search).

Per position: a 5 s `go movetime` search gives the stored depth D and its line. Then
`go depth D+1` is run once cold and once after `hint depth D pv <line>`, in alternating
order. Positions: `tools/bench_positions.hpp`, then `tools/openings.epd`; positions
solved before 5 s (mates found at once) are skipped.

## Result

| | seeded / cold | 95% CI (log-normal) |
|---|---|---|
| time, geometric mean | 0.975 | 0.873 – 1.088 |
| nodes, geometric mean | 0.979 | 0.883 – 1.084 |
| time, total | 0.960 (225.0 s / 234.3 s) | |
| nodes, total | 0.959 | |

Seeded was faster in 17 of 30. **The difference is not distinguishable from zero**: the
per-position spread (0.46 – 1.70) is much larger than the mean effect. Iterative
deepening finds the stored line again on its own, so the hint only helps the last
iterations' move order, and a changed move order moves LMR/null-move results both ways.
Scores at D+1 matched in 7/30 and the best move in 24/30: a different move order gives a
different (equally valid) alpha-beta result, never one the hint itself put there.

Decision: `PTT_SEED = true` (gui/ptt.hpp), the point estimate's side; it cannot change a
score, only the order the search tries moves in.
