# Weight set 7: w6 refitted twice on tune2 (#97)

`issue/97` at 4bd0aa9 (main 0411135 + `tools/bench weights=`), 2026-10-06.

## The fit

Two plain refits on `data/tune2` with w6's settings (K 302.22 fixed, lambda 1e-9, lr 2,
1500 epochs, best epoch by valid loss). The first, from w6, is #96's control run
(`data/hard/w7_tune2.txt`, `tools/tune` 05e6b35-dirty). The second starts from the first:

```
make tools/tune
./tools/tune data=<repo>/data/tune2 from=<repo>/data/hard/w7_tune2.txt out=w7_refit2.txt \
    k=302.22 jobs=4 tag=ccrl-cegt-tcec-3000-balanced     # 11:41 wall, 681 MB peak RSS
```

Loss on tune2, real eval:

| set | train | valid | test |
|---|---|---|---|
| w6 | 0.114630 | 0.114748 | 0.114560 |
| refit 1 (from w6) | 0.114101 | 0.114206 | 0.114012 |
| refit 2 (from refit 1) = **w7** | 0.113840 | 0.113938 | 0.113743 |

Refit 2's best epoch is 902, and each restart gains about half as much as the one before
(−0.00054, then −0.00027). A third would likely gain ~0.00013. (#104: it gains 0.00017, and
every run had reached its minimum; the gains come from lambda's anchor moving to each new
start, `tune_gn_2026-10-08.md`.) `weights/w7.txt` is refit 2
with `version 7`, `parent 6`.

Where the loss went: material. The opening values (all pieces on) fall and the endgame
values rise, and it is not a shift into the square tables or mobility. Effective value =
piece value + square-table mean + mobility at a typical count (N 5, B 7, R 7, Q 14):

| | w6 opening | w7 opening | w6 endgame | w7 endgame |
|---|---|---|---|---|
| pawn | 158 | 147 | 255 | 283 |
| knight | 534 | 415 | 757 | 919 |
| bishop | 587 | 463 | 820 | 978 |
| rook | 686 | 490 | 1263 | 1520 |
| queen | 1780 | 1498 | 2140 | 2600 |

At phase 12, midway, they barely move (rook 975 → 1005, queen 1960 → 2049). The fit keeps
spreading the two ends apart, a direction the data holds only weakly, since few positions sit
at either end with a material imbalance.
